Database management systems are software applications that provide a structured way to store, retrieve, and manage data. A database management system, also known as a DBMS, allows organizations to define, create, maintain, and control access to their data. There are several types of database management systems including relational databases, object-oriented databases, document databases, key-value stores, and graph databases. Relational databases organize data into tables consisting of rows and columns, where each row represents a record and each column represents a field or attribute of the data. Database normalization is the process of organizing data in a database to reduce redundancy and improve data integrity, with various normal forms defined from first normal form through fifth normal form. A primary key is a column or set of columns that uniquely identifies each row in a table, and a foreign key is a column or set of columns that establishes a referential relationship between two tables. SQL, which stands for Structured Query Language, is the standard language used to interact with relational database management systems, allowing users to create, read, update, and delete data as well as manage database schema. Indexes in databases are data structures that improve the speed of data retrieval operations, similar to how a book's index helps readers find information quickly without reading the entire book. Transactions in databases provide atomicity, consistency, isolation, and durability (ACID) properties, ensuring that database operations are processed reliably even in the case of system failures. A deadlock in database systems occurs when two or more transactions are waiting for each other to release locks on resources, creating a circular dependency that can halt execution. Database replication involves copying and maintaining database objects in multiple databases located on different servers, providing redundancy and improving read performance. Sharding, also called horizontal partitioning, splits a database into smaller, faster, more easily managed pieces called shards, with each shard containing a subset of the total data. NoSQL databases were developed to address limitations of relational databases for certain use cases, offering flexible schema design and the ability to handle unstructured and semi-structured data. Document databases store data in JSON-like documents, allowing nested data structures and flexible fields that can vary from one document to the next. Key-value stores, the simplest type of NoSQL database, store data as a collection of key-value pairs where each key uniquely identifies an item and the value can be any type of data. Graph databases use graph structures with nodes, edges, and properties to represent and store data, making them particularly suitable for social networks, recommendation engines, and fraud detection. Time-series databases are optimized for handling time-stamped data points, commonly used in monitoring applications, IoT sensor data, and financial trading systems. The CAP theorem states that a distributed system can only provide two of three guarantees simultaneously: consistency, availability, and partition tolerance, and since network partitions can never be fully avoided in distributed systems, designers must choose between CP and AP systems. Database indexing strategies include B-tree indexes for range queries, hash indexes for exact match lookups, and bitmap indexes for low-cardinality columns. ACID compliance ensures that database transactions are processed reliably, with atomicity guaranteeing all-or-nothing execution, consistency ensuring the database moves from one valid state to another, isolation preventing interference between concurrent transactions, and durability ensuring that once a transaction is committed it will persist even in the case of system failure. Write-ahead logging is a technique used by most database systems to provide atomicity and durability, where changes are written to a log file before they are applied to the database itself. Database connection pooling reduces overhead by maintaining a cache of database connections that can be reused across multiple requests rather than creating a new connection for each operation. The ORM, or object-relational mapping, layer provides an abstraction between application code and the underlying database, allowing developers to work with objects instead of raw SQL queries.

[More filler on software testing]

Software testing is a critical phase of the software development lifecycle that involves evaluating the functionality, quality, and performance of software applications. Unit testing focuses on testing individual components or functions in isolation to verify they work correctly in and of themselves. Integration testing verifies that different modules or services work together correctly as a combined subsystem. System testing evaluates the complete and integrated software system to verify it meets specified requirements. Black box testing techniques derive test cases from software specifications without any knowledge of internal implementation, while white box testing uses knowledge of internal logic to design test cases. Test-driven development, also known as TDD, is a software development methodology where tests are written before the code they are testing, driving design and ensuring high test coverage. Behavior-driven development, also called BDD, extends TDD by using natural language descriptions of software behavior to facilitate communication between developers, QA, and non-technical stakeholders. Code coverage metrics measure the proportion of source code that is executed during testing, with common coverage criteria including statement coverage, branch coverage, and path coverage. Performance testing evaluates how a software system behaves under various load conditions, including stress testing to identify breaking points and load testing to verify performance at expected normal and peak loads. Security testing identifies vulnerabilities in software systems through techniques including penetration testing, vulnerability scanning, and code review for security anti-patterns. Usability testing evaluates how easily users can learn and use a software application, measuring task completion time, error rates, and user satisfaction through structured studies with representative users.
